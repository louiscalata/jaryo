# Accessibility-tree and keyboard pass, 2026-11-07

**This is not a screen-reader test.** No VoiceOver, NVDA or TalkBack was used: turning one on changes system accessibility settings, and nobody listened to the pages end to end. What ran: the built-in browser pane's accessibility tree and DOM for three pages (the app reference, the website reference and one adaptor view, `adaptor-view-undeclared-fixture.html`; the other two adaptor pages come from the same template and were not exercised), plus real key presses (Tab, Enter, Escape) on that adaptor view. The adaptor view template was revised after the first look (review of the adaptor spike), and the keyboard path below was re-run on the revised page; its automated checks are in `tests/render.test.mjs`. The pages were rendered as static snapshots, not file origins.

## Adaptor view (`reference/adaptor-view-undeclared-fixture.html`)
Passed:
- Landmarks: banner and main; headings h1 then h2; the list of steps is a real list.
- Every step button has a name with its step id (or record id), state word and reason, for example "Check file hashes, step id check_hashes, ok".
- Real Tab order: steps first, then the actions. Enter selects a step and focus stays on it; the live region says "Selected …".
- Enter on "Preview the run review (does nothing)" opens the review with its Close button focused and the consequential step named; Escape closes it and focus returns to the opener.
- Selecting a step updates the buttons in place, so keyboard focus stays on the selected step. The scrollable output block is a labelled, focusable region.
- Not-available actions have names that include the reason ("pause, not available. n/a: manifest does not declare pause").
- No console errors; no horizontal overflow at the pane width.

Fixed during the pass: step names lacked the step id; n/a actions did not expose their reason; no main landmark.

## App reference (`reference/index.html`; findings applied in v0.5e)
Passed: lang, title, no unnamed controls, no duplicate ids, no broken aria references, both dialogs named, two live regions, step names include the id and state.
Findings, all applied in v0.5e (Codex rounds 14–15, `tests/reference-a11y.test.mjs`):
1. No `main` landmark and no h1 (landmarks are header, aside, nav only).
2. Step names read the glyphs aloud: "● [OK]", "? [UNKNOWN]". A screen reader may announce symbol names.

## Website reference (`reference/hero.html`; findings applied in v0.5e)
Findings, all applied in v0.5e:
1. `aria-label` on a `<span>` and two `<pre>` elements has no role, so most screen readers ignore it, and the Before/After distinction is not shown visually.
2. The nav links "How it works", "Adaptors", "Docs" point to anchors that do not exist.
3. "Open connect UI" is a link used as a button (it only runs a script).
